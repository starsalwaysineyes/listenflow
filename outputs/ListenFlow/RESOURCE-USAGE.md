# 持续转写资源采样

> 「持续转写资源采样」两节的数据来自**本地模型**引擎（Qwen3-ASR 常驻进程）。0.8.0 起默认引擎是豆包云端识别，这时不启动 ASR 子进程，那两节的 ASR 行和约 2.7 GB 内存不适用。豆包引擎下录制中的整体 CPU 和内存仍未采样；空闲占用和几条热路径的耗时见文末「0.11.0」。

采样时间：2026-10-10 19:45:14–19:45:45，中国标准时间。

场景：0.1.0 正在采集腾讯会议，Qwen3-ASR 1.7B 常驻识别，麦克风关闭。未运行编译或额外模型测试。对主进程与 ASR 子进程每 5 秒取样；首个累计样本不计入 CPU 平均。

| 进程 | 平均 CPU | CPU 范围 | 内存占用（系统 top MEM） |
|---|---:|---:|---:|
| 听流界面与采集 | 45.3% | 37.1–47.8% | 约 41 MB |
| ASR 子进程 | 8.4% | 4.6–11.2% | 约 2.65 GB |
| 合计 | 53.7% | — | 约 2.7 GB |

macOS 的进程 CPU 百分比以一个核心为 100%。两进程合计约 0.54 核，相当于本机 10 核总 CPU 容量的约 5.4%。ASR 使用 Metal/GPU，此 CPU 数字不是总计算负载；未测 GPU 利用率、功耗或电池续航。

采样期间整机 CPU 空闲约 45–55%（首样本约 34%）。已有约 3.7 GB 整机交换空间占用，但采样期间没有新增 swap-in / swap-out，不能把历史换页量归因于听流。系统未报告热或性能警告。

0.2.0 把电平条更新从整个窗口的可观察状态中分离，并把电平刷新降为每秒最多 5 次，减少重复计算界面。上表为 0.1.0 的真实数据；后续 0.2.1 复测见下文。

## 0.2.1 复测

采样时间：2026-10-10 20:03:56–20:04:22，中国标准时间。选定独立测试播放器，循环播放本机 27 秒中文语音，麦克风关闭，ASR 仍为 Qwen3-ASR 1.7B，显示原始转写，自动整理关闭。

完整记录采了 7 个样本；剔除初始化样本和首个间隔（该间隔有一次短暂的测试程序编译），保留 5 个稳定间隔，约 26 秒。

| 进程 | 平均 CPU | CPU 范围 | 内存（top MEM） |
|---|---:|---:|---:|
| 听流界面与采集 | 15.62% | 15.0–16.1% | 85–87 MiB |
| ASR 子进程 | 5.64% | 4.3–8.5% | 2708–2720 MiB |
| 合计 | 21.26% | — | 约 2.73–2.74 GiB |

合计约 0.21 个 CPU 核心，约占本机 10 核总 CPU 容量的 2.1%。本次测试最后保存 16 段转写，平均延迟 4.36 秒，最大 4.43 秒；稳定采样间隔没有新增换页，系统未报告热或性能警告。未测 GPU 利用率、功耗、电池续航。

旧版参考采样合计 53.7% CPU（约 0.54 核）。新版本次占用更低，但两次音源、文字长度和窗口状态不同，不能把两数之差当作严格的同场景优化收益。新样本不包含自动整理的 API/预览开销。
